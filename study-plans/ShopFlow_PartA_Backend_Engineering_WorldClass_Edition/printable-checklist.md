# ShopFlow Part A - Backend Engineering: Printable Checklist

## Daily Rules
- [ ] Study for 2 to 3 hours.
- [ ] Work 6 days.
- [ ] Use day 7 for retrospective.
- [ ] Write one short summary.
- [ ] Write one open question.

## Week 1: Backend orientation

### Day 1
- [ ] Read headings and create a topic map.
- [ ] List backend responsibilities.
- [ ] Write the main question the PDF answers.

### Day 2
- [ ] Read the opening sections.
- [ ] Summarize the backend role.
- [ ] Distinguish backend work from frontend work.

### Day 3
- [ ] Capture backend concepts as definitions.
- [ ] Add unfamiliar terms to a glossary.
- [ ] Write a plain-language explanation for each.

### Day 4
- [ ] Study examples or diagrams.
- [ ] Rewrite them as flows.
- [ ] Note what the PDF emphasizes.

### Day 5
- [ ] Group ideas into categories.
- [ ] Organize notes by APIs, services, data, and operations.
- [ ] Mark repeated concepts.

### Day 6
- [ ] Recreate the topic map from memory.
- [ ] Explain the PDF in two minutes.
- [ ] Mark sections for a slower pass.

### Day 7
- [ ] Review the week.
- [ ] Write what is clear and what is abstract.
- [ ] Choose the next section to revisit.

## Week 2: APIs and request flow

### Day 8
- [ ] Re-open the outline.
- [ ] Read the request-handling sections.
- [ ] Write the major API decisions.

### Day 9
- [ ] Trace a request end to end.
- [ ] Write each stage as a flow.
- [ ] Note validation, routing, and transformation.

### Day 10
- [ ] Study service boundaries.
- [ ] Write what belongs inside and outside a service.
- [ ] Capture coupling guidance.

### Day 11
- [ ] Review naming and contract guidance.
- [ ] Summarize the rules.
- [ ] Add one good API shape and one bad one.

### Day 12
- [ ] Sketch a sample request-response cycle.
- [ ] Annotate errors, validation, and success states.
- [ ] Compare it to the PDF.

### Day 13
- [ ] Recap API design principles from memory.
- [ ] Write what makes an API easy to use.
- [ ] List remaining questions.

### Day 14
- [ ] Retrospective day.
- [ ] Review request-flow notes.
- [ ] Decide what to reread next.

## Week 3: Data, validation, and reliability

### Day 15
- [ ] Revisit persistence and data notes.
- [ ] Identify reliability topics.
- [ ] Mark consistency and integrity ideas.

### Day 16
- [ ] Study validation rules.
- [ ] Summarize where validation should happen.
- [ ] Write invalid-input examples.

### Day 17
- [ ] Focus on error handling.
- [ ] List failures discussed in the PDF.
- [ ] Note what to do when things break.

### Day 18
- [ ] Review resilience, retry, timeout, or fault-tolerance ideas.
- [ ] Write each as a purpose-plus-effect pair.
- [ ] Add caution notes.

### Day 19
- [ ] Summarize maintainability practices.
- [ ] Note design choices that improve changeability.
- [ ] Highlight complexity-reducing patterns.

### Day 20
- [ ] Do a closed-book recap of data and reliability.
- [ ] Rebuild the reliability checklist.
- [ ] Test definitions and tradeoffs.

### Day 21
- [ ] Retrospective day.
- [ ] Write the top reliability habits.
- [ ] Choose the weakest failure scenario to revisit.

## Week 4: Applied review and synthesis

### Day 22
- [ ] Review all summaries.
- [ ] Identify the top backend ideas.
- [ ] Note repeated recommendations.

### Day 23
- [ ] Re-read the weakest sections.
- [ ] Rewrite them more simply.
- [ ] Remove vague phrasing.

### Day 24
- [ ] Create a backend principles sheet.
- [ ] Include API shape, boundaries, data, and reliability.
- [ ] Keep each principle actionable.

### Day 25
- [ ] Build a practical example using multiple ideas.
- [ ] Describe flow, data, and error handling.
- [ ] Record what the example teaches.

### Day 26
- [ ] Review the PDF from memory first.
- [ ] Compare memory notes to the source.
- [ ] Correct inaccuracies.

### Day 27
- [ ] Write the final backend summary.
- [ ] Include the main rules and biggest lessons.
- [ ] Add one future practice item.

### Day 28
- [ ] Run a final closed-book self-test.
- [ ] Explain the PDF from memory.
- [ ] Mark remaining weak spots.

### Day 29
- [ ] Review self-test results.
- [ ] Fix mistakes in notes.
- [ ] Write the last unresolved question.

### Day 30
- [ ] Final retrospective.
- [ ] Summarize what you learned.
- [ ] Decide how to revisit the material later.
